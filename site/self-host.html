Self-host

Run it yourself

coolpsonotes is one small server: a Rust binary, a SQLite file and the web app. Here is how to try it, run it for real, and keep it safe.

Try it first

Development mode needs no sign-in provider. Sign in as any name, then open a second browser tab and sign in as someone else to try sharing and live editing between two people.

Never expose development mode to a network: anyone can sign in as anyone.

# with Docker
$ docker compose -f docker-compose.dev.yml up --build

# or from source (Rust, wasm32 target, wasm-bindgen)
$ task setup
$ task dev

# then open http://localhost:8080

Run it for real

You need a machine with Docker, a domain name pointing at it, and an OpenID Connect provider such as Authelia, Keycloak, Authentik or Google. The included Compose file runs coolpsonotes behind Caddy, which gets HTTPS certificates automatically.

Register coolpsonotes with your provider, with the redirect address https://your.domain/api/v1/auth/oidc/callback, and put the details in .env.

The first person to sign in becomes the administrator.

$ git clone https://github.com/coolapso/coolpsonotes
$ cd coolpsonotes
$ cp .env.example .env
# PUBLIC_HOST=notes.example.com
# OIDC_ISSUER=https://auth.example.com
# OIDC_CLIENT_ID=coolpsonotes
# OIDC_CLIENT_SECRET=…
$ docker compose up -d --build

Back it up

Everything lives in one SQLite database: encrypted notes, attachments and keys wrapped for members. A backup is a consistent copy of that file, made while the server runs. Backups are encrypted data too; they need people's own keys to read.

$ docker compose exec coolpsonotes \
    coolpsonotes-server backup --out-dir /data/backups --keep 14

The desktop client

Build the coolpsonotes command-line client, sign in once per computer, and keep your vaults as a folder of Markdown files that you edit with any editor.

Use your own editor · All CLI commands

$ cargo install --path crates/client --locked
$ coolpsonotes login --server https://notes.example.com
$ coolpsonotes sync --dir ~/Notes

Going further

  • KubernetesManifests for a single replica with a persistent volume and a backup CronJob.
  • Other reverse proxiesnginx and Traefik work too; the server needs WebSockets and the forwarded client address.
  • MonitoringPrometheus metrics, health and readiness endpoints.
  • UpgradesDatabase migrations run on start, after an automatic backup.

Configuration, identity providers, proxies, backups and upgrades are covered in docs/operations.md.
